### D 节的取证结论在哪、哪些只在总账里

八轮只读取证（22 张表 + `DB all` 的 276 张表名全集）的**过程、逐轮读数与五处自纠**记在取证存档里（下面几个名字，不随这一支），本表不再复述：
`E2631_DB_SNAPSHOT`（逐轮结果，含 §13"配置库解决不了的那几件"）、
`E2631_DB_TABLES`（mesh 相关的表是 **19 张**（10 `MultiAP*` + 9 `P1905*`）而不是 5 张；`MESH`/`Netsphere`/`EASYMESH` 不在 276 张里，只当 web 层名称映射）、
`E2631_ROOTFS`（整块 rootfs 与 `/etc/autouserconf` 的 612 个编译期开关）、
`VENDOR_MESH_STACK` 第 5 节（分级）。上表右列就是那八轮的结论。

结案的几条线（读数与推证过程在存档，这里只留结论）：**角色是静态配置出来的 Slave**（`MapCooperatorCfg` 与 `MultiAPCfg` 六个开关同向，不选举、不自动开局、重启也不改主意）；**band 归属** `Radio.1`=2.4G、`Radio.2`=5G（`WLANBase` 两行同报 MT7916，与 [FINDINGS](FINDINGS.md) §10 记的 Z506 射频 MT7592/MT7613 不是同一套，"不支持 160"那句不能套到本机）；**`PortState=4` = 在跑**（配置侧 `WLANCfg.Enable` + 物理侧"只有 LAN2 插着网线"双证闭合）；**真实 SSID 名在 `MultiAPDomain.ESSID`（明文），`WLANCfg.ESSID` 与 `WLANPSK` 的密钥都被遮蔽成 `***`——名字可还原、密钥不行**（遮蔽按表/列做，不是全局策略）。

只有总账需要留下的三条（它们管的是本表怎么被读，不是读数）：

- **`sendcmd 1 DB p` 这条线已到头**：D3–D7 加角色、band、端口拓扑的**库侧入口**都是实测级，但**功能本身一项都没实测**，所以 D 节一项都不改成 ✅；换手段才动得了（位图/枚举语义 → 反汇编或 Multi-AP 规范正文；厂商启用 VLAN 写哪侧 → web `.lua`；1905 实际跑在哪几个接口 → `pktdump 1` / `/proc/net/dev`）。真实路由器上的行为见 [PLAN](PLAN.md) H-07。
- **表名不许猜、行名不是表名**：先 `DB all` 列全集（`DB l` 不存在）；`IGD.P1905CFGn` 是 `P1905Cfg` 的**行名**；`RowCount=0` 只说明出厂没配，**不否证落点**；`P1905Cfg` 只能证明"允许跑在哪些接口"，不能证明"在跑"。
- **`isSave=0` 的列只能读状态、不能当配置比对**（写 DB 不落盘；`WLANSSID` 整表、`WLANCfg.IfName`、`MultiAPDomain.ESSID` 都是）——拿它当配置依据会判错，反过来"改了不生效"也别急着说固件不认。同一台设备上"支持某能力"一律指"编进去了"，不指"开着"。

> **B16 已结案（一句话）**：`MultiAPCfg.CurHop=2=MaxHop` 且 `EnMasterOnly=0`，与 [SCHEMA](milestones/SCHEMA.md) 的"`EnMasterOnly=1` 时 `slave_init` 跳过、`CurHop` 不会被设成 `MaxHop`"条件句三者自洽——不是"读到一个值"式的结案。存档见 `E2631_DB_SNAPSHOT` §6.3。
